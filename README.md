# FoxyforVPS

داشبورد self-hosted اوبونتو برای مدیریت خروجی‌های SOCKS5 لوکیشن‌های Firefox VPN، پورت‌ها، quota و سرویس‌های پنل. Firefox Accounts دسترسی این پروژه را تضمین یا پشتیبانی رسمی نمی‌کند.

## ورود مستقیم Firefox از پنل

پنل از مسیر API حساب Firefox استفاده می‌کند و Chromium یا افزونهٔ مرورگر اجرا نمی‌کند. رمز از طریق HTTPS یا تونل SSH به backend VPS می‌رسد و همان‌جا به مقدار `authPW` تبدیل می‌شود؛ رمز خام به API ورود Firefox ارسال نمی‌شود. برنامه رمز را در فایل، دیتابیس، command line، environment یا log نگه نمی‌دارد و پس از درخواست reference آن را کنار می‌گذارد. بااین‌حال، مدیر root VPS از نظر فنی قادر به مشاهدهٔ داده‌های برنامه است؛ فقط روی VPS خودت استفاده کن.

اگر API تأیید ایمیلی، TOTP، لینک ایمیل یا کد رفع مسدودی بخواهد، پنل مرحلهٔ مربوط را نمایش می‌دهد. پاسخ HTTP 406 به معنی چالش امنیتی شبکهٔ Firefox است؛ این نسخه آن را دور نمی‌زند و تلاش را با پیام مشخص متوقف می‌کند. نتیجهٔ ورود به IP و تصمیم‌های امنیتی Mozilla وابسته است؛ موفقیت API login تضمین‌شده نیست. پس از تلاش ناموفق، رمز، کد تأیید یا session token را در issue یا گفتگو نفرست.

## نصب و به‌روزرسانی Ubuntu

پس از قرار دادن فایل‌ها در شاخهٔ `main` مخزن `arefhere51/FoxyforVPS`:

```bash
curl -fsSL https://raw.githubusercontent.com/arefhere51/FoxyforVPS/main/manager.sh | sudo bash -s -- install
```

نصب، وابستگی‌های Python، core سفارشی sing-box و سرویس‌های systemd را آماده می‌کند. در نسخهٔ جدید Chromium نصب نمی‌شود؛ اگر نسخهٔ قدیمی حساب اختصاصی مرورگر FoxyforVPS ساخته باشد، updater همان حساب و فایل‌های مرورگر را پاک می‌کند.

پس از نصب، رمز اولیهٔ پنل یک‌بار در ترمینال نمایش داده می‌شود. آن را در password manager ذخیره کن و از فرم **تغییر رمز ورود به پنل** رمزی با طول دلخواه ۱ تا ۲۵۶ نویسه انتخاب کن. رمزهای کوتاه، به‌ویژه برای پنل عمومی، ریسک بالاتری دارند. رمز جدید با PBKDF2 salted hash در فایل root-only ذخیره می‌شود؛ رمز تصادفی اولیه نیز root-only است.

```bash
sudo foxyforvpsctl menu
sudo foxyforvpsctl update
sudo foxyforvpsctl status
sudo foxyforvpsctl remove
```

بعد از تغییر رمز پنل، مرورگر را دوباره احراز هویت کن.

## پنل خصوصی از طریق SSH

backend فقط روی `127.0.0.1:8778` VPS گوش می‌دهد. روی رایانهٔ خودت این تونل را باز و باز نگه‌دار:

```bash
ssh -L 8777:127.0.0.1:8778 USER@VPS
```

سپس `http://127.0.0.1:8777` را باز کن. در این حالت ترافیک از اتصال SSH محافظت می‌شود و فرم ورود Firefox می‌تواند به backend محلی تونل‌شده ارسال شود.

## پنل عمومی HTTPS روی پورت 8777

برای فعال‌سازی اولیه، یک نام دامنهٔ تحت کنترل خودت بده که DNS عمومی آن مستقیم به **IP عمومی همین VPS** برسد. پس از به‌روزرسانی، Caddy از on-demand TLS استفاده می‌کند: نام‌های دامنهٔ دیگری هم که DNS عمومی‌شان فقط به همان IPهای VPS resolve شود، بدون اجرای دوبارهٔ `public enable` قابل استفاده‌اند. درخواست گواهی فقط پس از بررسی DNS و اعتبارسنجی CA پذیرفته می‌شود؛ Caddy نیز توصیه می‌کند on-demand TLS حتماً با ask endpoint محدود شود [مستند Caddy](https://caddyserver.com/docs/automatic-https). backend همچنان روی loopback:8778 خصوصی می‌ماند و HTTP خام روی اینترنت فعال نمی‌شود.

اگر listener عمومی از نسخهٔ قبلی فعال است، پس از قراردادن نسخهٔ جدید در مخزن `sudo foxyforvpsctl update` را اجرا کن؛ updater تنظیم Caddy فعال را پس از بررسی، به حالت دامنه‌های پویا منتقل می‌کند.

پس از ثبت DNS اجرا کن:

```bash
sudo foxyforvpsctl public enable vpn.example.com
```

پنل در `https://vpn.example.com:8777` باز می‌شود؛ دامنه‌های دیگر هم باید مستقیم به همان VPS اشاره کنند. اگر از Cloudflare استفاده می‌کنی، رکورد را روی **DNS only / ابر خاکستری** بگذار: Cloudflare پورت HTTPS شمارهٔ 8777 را در proxy معمولی پشتیبانی نمی‌کند [فهرست رسمی پورت‌ها](https://developers.cloudflare.com/fundamentals/reference/network-ports/). برای صدور و تمدید گواهی، TCPهای 80، 443 و 8777 را در firewall ارائه‌دهنده و UFW مجاز کن. تعداد بسیار زیاد دامنه‌های متفاوت می‌تواند به محدودیت صدور گواهی CA برسد [حدود Let's Encrypt](https://letsencrypt.org/docs/rate-limits/). اگر Caddy/Nginx/Apache یا سرویس دیگری روی پورت‌های موردنیاز فعال باشد، برنامه از بازنویسی آن خودداری می‌کند.

برای خاموش‌کردن دسترسی عمومی:

```bash
sudo foxyforvpsctl public disable
```

## پراکسی‌ها

هر ورودی فقط SOCKS5 است و بدون نام‌کاربری/گذرواژه کار می‌کند. چون سرویس روی رابط عمومی VPS گوش می‌دهد، هر پورت قابل‌دسترسی از اینترنت به پراکسی باز تبدیل می‌شود. فایروال VPS و firewall ارائه‌دهنده را طوری تنظیم کن که پورت‌های فعال فقط از IPهای مورداعتماد خودت قابل‌دسترسی باشند؛ بازگذاشتن آن‌ها برای همهٔ اینترنت می‌تواند به سوءاستفاده، هزینهٔ ترافیک یا مسدودشدن VPS منجر شود. فایروال خودکار تغییر نمی‌کند. مصرف چند لوکیشن از quota مشترک همان حساب است. دسترسی نهایی هر لوکیشن را Mozilla تعیین می‌کند.

## رمزها و داده‌ها

- گذرواژهٔ Firefox فقط در جریان login از راه HTTPS/SSH به VPS می‌رسد؛ برنامه آن را در storage دائمی نمی‌نویسد و بعد از نتیجهٔ درخواست referenceهای آن را کنار می‌گذارد. مقدار `authPW` به API حساب Firefox فرستاده می‌شود.
- session token و کدهای تأیید فقط در حافظهٔ backend و حداکثر ۱۵ دقیقه برای ادامهٔ ورود نگهداری می‌شوند؛ در صورت موفقیت token با OAuth مبادله و درخواست حذف آن به FxA ارسال می‌شود. اعتبارهای OAuth لازم برای سرویس در `/var/lib/foxyforvps/` باقی می‌مانند.
- رمز پنل پس از تغییر با PBKDF2 salted hash در `/etc/foxyforvps/admin-password` ذخیره می‌شود؛ فایل فقط root قابل خواندن است.
- پنل public فقط روی HTTPS و TCP 8777 در دسترس است؛ backend روی VPS loopback:8778 قرار دارد.
- quota از پاسخ API دریافت می‌شود؛ اگر در پاسخ نباشد، داشبورد «نامشخص» نشان می‌دهد.

## مجوز و سازگاری

FoxyforVPS یک پروژهٔ غیررسمی است و ممکن است با تغییرهای Mozilla Accounts/FxA یا firewall شبکه از کار بیفتد. کد protocol بر اساس FoxyVPN و fork متن‌باز sing-box تنظیم شده است. قبل از فعال‌کردن تعداد زیادی خروجی، یک لوکیشن را آزمایش کن.
